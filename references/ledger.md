# Ledger

## File

`ledger.jsonl` in the corpus root - append-only, one JSON object per line. `ledger.md`
is the human view, regenerated by `ledger.py render` - never edit it by hand.

## Entry shape

```json
{
  "date": "2026-08-29",
  "company": "ExampleCo-Role",
  "role": "Internal IT Support / Helpdesk (game studio)",
  "keywords_total": 54,
  "coverage": "54/54",
  "pages": 2,
  "audit_passed": true,
  "bullets_shipped": ["M1-game", "M3-game", "M4-game", "M5-game", "M6-new"],
  "output_docx": "ExampleCo-Role/resume.docx",
  "output_pdf": "ExampleCo-Role/resume.pdf",
  "jd_path": "ExampleCo-Role/JD.md",
  "notes": "free-form"
}
```

## Append and render

```bash
python3 scripts/ledger.py append '{"date":"2026-08-29","company":"Acme",...}'
python3 scripts/ledger.py append entry.json   # JSON object in a file also works
python3 scripts/ledger.py render               # regenerates ledger.md from ledger.jsonl
```

## JD archiving

Save the verbatim JD to `<Company>/JD.md` at Step 1 - it enables re-tailoring, interview prep, and "why this keyword" audits.

## Migration

The old hand-edited `ledger.md` (two rows, 2026-08-29) was migrated to `ledger.jsonl` by the improvement pass and `render` now owns the human view.
